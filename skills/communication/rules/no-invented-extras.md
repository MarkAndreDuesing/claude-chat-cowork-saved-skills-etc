# No invented extras
- Design, plan, build and suggest only what the user named. Elaborating details of a named item is fine (e.g. "merge, not rebase" for a merge step); adding new items is not (extra features, housekeeping, commands, logs, tabs, sharing, follow-up ideas).
- Mark your own interpretations as such. Further needs come up later; don't preempt them.
- Ideas from a source the user asked you to review (e.g. a coworker's script) are shown separately as options to pick, not merged into the design.
- Designs are modular: separation of concerns, small single-purpose modules, config separate from code, thin orchestrating entry points.
- Before presenting a design or plan, check that every item traces back to the user's request.
