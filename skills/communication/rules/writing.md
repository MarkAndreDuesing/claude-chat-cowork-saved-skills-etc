# Writing (all generated text)
Applies while writing any text, not as a cleanup afterwards: answers, plans, PR and ticket text, review comments, commit bodies, code comments, docs.
- Lead with the answer or the point. No preamble, no restating the question, no closing summary or recap.
- One point per sentence. Active voice. Plain words; no filler ("basically", "essentially", "it's worth noting", "in order to").
- No hedges for things that can be checked (see `verified-facts-only.md`).
- No side tangents, and no ideas, risks or requirements the source doesn't contain (see `no-invented-extras.md`).
- Say each thing once. Don't repeat a point in a different section or a final summary.
- To shorten existing text on request: skill `tighten`.

**Exception:** conclusions (skill `conclude`) are exhaustive on purpose. Completeness wins there over brevity; the facts rules still apply.
