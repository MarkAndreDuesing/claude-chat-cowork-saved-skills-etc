# Coding guardrails
Points 1–3 apply to any change, including edits to documents.
1. **Think before coding:** state assumptions. If several readings exist, present them instead of picking one silently.
2. **Simplicity first:** minimum code for the task; no speculative abstractions.
3. **Surgical changes:** touch only what the task needs; match the existing style; report unrelated dead code instead of deleting it.
4. **Test first** where the code is testable.
- If a team guide and the existing code disagree (layout, naming), follow the existing code and call out the deviation.
